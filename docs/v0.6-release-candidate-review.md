## リリースノート

v0.6.0では、締め済み勤怠を給与ソフトへ渡すための汎用給与連携CSVを追加した。所有者または労務管理者は、UTF-8 BOM・CP932、改行、ファイル名、列順、勤怠ソース、固定値、空欄、必須値、日付・年月、整数分、`HH:MM`、小数時間、丸め、区分対応、CSV数式注入方針をプロファイルとして設定できる。

プロファイルは変更可能なドラフトと不変な連番公開版を分離し、設定JSONを個人情報なしで移出入できる。Kinmu-OS従業員と利用先の外部従業員コードはプロファイル単位で個別またはCSV一括設定し、重複・未知従業員・空値を全行検査してから原子的に反映する。

出力は最新の締めリビジョン、公開プロファイル版、コード対応を再検査し、エラー0件の場合だけ生成する。CSV本体はDBへ保存せず、締めリビジョン、公開版、コード対応スナップショット、検査要約、生成者、行・列・byte数、SHA-256を追記型runへ保存する。過去runは不変マニフェストから再生成し、ハッシュ一致時だけ再ダウンロードできる。

月次再開・再締め後も旧runを削除せず「旧リビジョン」と表示し、新しい締めリビジョンでは再検査と明示的な新規生成を求める。設定、コード対応、検査、生成、再生成、再ダウンロード、整合性エラーは監査ログへ個人データを複製しない要約として記録する。

## 性能スモーク

100名、31日、60列の代表データで、UTF-8 BOM版とCP932版、複数のプロファイル公開版・runを作成した。全件検査、25行ページングプレビュー、生成、履歴一覧、SHA-256再ダウンロードを測定し、各処理が3秒未満であることを検証した。テスト全体の処理本体は約1.9秒で、月単位の一括取得により代表データ上のN+1基準超過はなかった。この値は開発機上のスモーク基準であり、本番環境のSLAではない。

## 更新とロールバック

更新前に、処理中の月次操作を完了し、直近の確定CSVを利用先と照合してから次を実行する。

```sh
BACKUP_DIR=/secure/backups scripts/backup.sh
scripts/update.sh
```

更新後はヘルスチェック、既存所有者のログイン、直近の締め状態・リビジョン・通常勤怠CSVを先に確認する。その後、汎用給与連携ドラフトを開き、列・文字コード・時間表現を確認し、外部従業員コード設定と全件検査を完了してから明示的に公開・生成する。汎用ドラフトは未公開で作成されるため、確認前に給与CSVが自動生成されることはない。

確実な切り戻しは、更新前バックアップを新しい空DBへ復元し、v0.5アプリを接続する方法である。破壊的なdown migrationは提供しない。実地確認では、v0.6データを持つDBへv0.5アプリを接続した場合、ヘルスチェック、既存ログイン、既存勤怠参照はHTTP 200だが、給与連携APIは404となり、v0.6のプロファイル・コード対応・runを閲覧または運用できなかった。

そのため、次を守る。

- 切り戻し判断中は新規入力と給与連携ファイルの配布を停止する。
- v0.6で作成した給与プロファイル、コード対応、run、監査をv0.5で変更できるとみなさない。
- v0.5へ戻した状態で勤怠を変更してから、同じDBを再度v0.6へ進める運用を行わない。
- v0.6データを持つDBへv0.5アプリを接続したまま継続運用せず、原則として更新前バックアップを空DBへ復元する。
- 更新後の入力は更新前バックアップへ自動的に取り込めないため、必要な再入力と監査上の扱いを決めてから切り戻す。

## 既知の制限

- 給与、税、社会保険料、割増賃金、36協定その他の法令適合を計算・判定しない。
- 給与サービスAPI同期、振込データ、給与明細、年末調整データは提供しない。
- 任意JavaScript、SQL、任意式、列間参照、利用者定義プラグインを実行しない。
- v0.6初期版は汎用一人一行CSVであり、多数のベンダー固有プリセットや日次複数行形式は提供しない。
- CP932で往復一致しない文字は欠落させず生成を拒否する。必要に応じてUTF-8 BOMへ切り替える。
- 過去runの互換生成器が将来失われるかハッシュ不一致になった場合、履歴は保持するが再ダウンロードを拒否する。
- v0.6で作成した給与連携データはv0.5アプリから利用できない。
