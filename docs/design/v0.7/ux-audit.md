# v0.6 UI audit and v0.7 acceptance

## Current gaps

- 左メニューが一階層で、設定、審査、月次の関係が見えにくい
- ページ見出しはあるが、対象、現在状態、完了条件、次の操作がページごとに異なる
- フォーム入力が同じ幅になりやすく、単位、例、必須・任意、影響が不足する
- 空表示が未設定、0件、検索0件、締め済みを十分に区別しない
- 成功が一時通知だけの画面があり、次の確認先が残らない
- 一覧が狭幅で横スクロール中心になり、主要項目と次の操作を追いにくい
- 対象月や絞り込みを保った往復動線が画面ごとに異なる
- 処理中、操作不可、未保存の理由が常に説明されない

## Acceptance checklist

### First glance

- ページ名、目的、対象、状態、主要操作が最初の画面内にある
- 主要操作は通常一つで、結果を表す動詞を持つ
- ガイドへ移動し、安全に元画面へ戻れる

### Forms

- 全入力に可視ラベルがある
- 必須・任意、単位、例、制約が必要に応じて表示される
- short / medium / long / fullが入力内容と一致する
- 320pxでも横スクロールせず、44px以上で操作できる
- 未保存、送信中、失敗、競合、成功を区別する

### Lists

- 総件数、表示件数、対象条件、並び順を確認できる
- 状態と対応要否を色以外でも判別できる
- 100名規模で見出しと主要列を追跡できる
- モバイルでは主要情報カードから詳細へ到達できる

### Navigation

- 最大二階層、役割別カテゴリ、現在カテゴリ自動展開
- パンくずと現在項目が一致する
- モバイルの「すべて」で全機能へ到達できる
- 詳細・審査後に安全な対象月と条件を保って戻れる

### Accessibility and security

- キーボードで主要導線を完了できる
- 見出し、ラベル、説明、エラー、live regionが関連付く
- 権限のないカテゴリ、件数、他組織識別子を露出しない
- 任意の外部URLを戻り先として使用しない
