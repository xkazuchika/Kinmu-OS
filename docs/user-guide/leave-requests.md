# 休暇申請・審査・欠勤確定

対象バージョン: 0.8.0

## 従業員が全日・半日休暇を申請する

1. 「休暇」で種別別の利用可能残高、審査待ち予約、次回失効を確認します。
2. 休暇種別、全日または半日、開始日、終了日、申請理由を入力します。半日は1日だけ指定します。
3. 「対象日と残高を確認」を選び、休日として除外された日、勤務予定、必要日数、申請後残高を確認します。
4. 「この内容で申請」を選び、状態が審査待ちになったことを確認します。

審査待ちまたは差し戻し中の自分の申請だけを取り消せます。管理者が代理作成した自分の申請も「申請履歴」で確認・取消できます。承認済み・却下済み申請や締め済み月は変更できません。

## 管理者が審査する

1. 「承認受信箱」で審査待ち申請を選びます。
2. 対象日、全日・半日、勤務予定、打刻、既存休暇、台帳残高、審査待ち予約、付与ロット、申請時部署、担当、期限、改訂履歴を確認します。
3. 承認する場合は確認ダイアログから確定します。残高は有効期限の早い付与から消化されます。
4. 修正できる不足は具体的な理由付きで差し戻し、終了する場合は理由付きで却下します。

自分の申請は自分で承認・却下できません。承認直前に打刻、重複、残高、締め状態が変わった場合は競合として停止するため、最新状態を確認します。

## 差し戻しと再申請

差し戻された申請は審査待ち予約から外れます。「申請履歴」で理由と過去版を確認し、休暇種別、対象日、単位、理由を修正して再申請します。再申請時は現在の勤務予定、休日除外、打刻、重複、残高、締め状態を再検証し、通過した場合だけ新しい改訂と予約を作ります。

管理者が代理作成する場合も通常と同じ残高・競合・締め検証を行い、対象従業員、実際の作成者、代理理由を分けて記録します。

## 未解決日を欠勤へ確定する

管理者は過去の未締め所定勤務日で、打刻も承認済み休暇もない日を理由付き欠勤へ確定できます。欠勤は休暇残高を消費しません。誤りがある場合は月次締め前に勤怠と休暇の状態を確認してください。

## 月次締めとの関係

審査待ちまたは差し戻し中の休暇、未解決の所定勤務日、日区分競合は月次締めを止めます。[月次勤怠の締め・再開](monthly-closing.md)の手順で各件数を0にしてから締めます。締め済みリビジョンには休暇名・単位・対応所定時間、カレンダー根拠、欠勤理由が固定保存されます。

## 画面の目的

従業員は残高と対象勤務日を確認して休暇を提出し、管理者は勤務予定・打刻・残高を確認して審査します。

## 入力項目

休暇種別、全日・半日、開始日、終了日、申請理由を入力します。却下時と欠勤確定時は、本人が判断経緯を理解できる具体的な理由が必要です。

## 完了条件

提出後に状態が「審査待ち」となり、審査後に「承認済み」または理由付き「却下」が表示されれば完了です。

## 次の操作

従業員は申請履歴または通知を確認します。管理者は審査待ちを0件にして[月次勤怠の締め・再開](monthly-closing.md)へ進みます。

## トラブル対処

残高不足、休日だけの期間、重複、締め済み、更新競合では送信・審査を停止します。入力値と最新状態を確認し、解消しない場合は[トラブル対処](troubleshooting.md)を参照してください。

## 現行版の制限

時間単位休暇、自動法令判定、多段承認には対応していません。集計と申請承認は法令や就業規則への適合を判定するものではありません。
