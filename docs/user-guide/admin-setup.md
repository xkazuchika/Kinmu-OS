# 初期設定と従業員管理

対象バージョン: 0.8.0

## 対象役割と開始画面

対象役割は所有者と労務管理者です。最初の組織と所有者は `/setup` から作成し、その後はホームから各管理画面へ進みます。

## 初期設定

1. 組織名、所有者名、所有者メールアドレス、タイムゾーンを入力します。
2. 発行された設定リンクを開き、12文字以上のパスワードを設定します。
3. ログイン後、ホームが表示されることを確認します。

## 利用者管理

1. 「利用者管理」を開き、氏名、メールアドレス、役割を入力します。
2. 設定リンクを本人へ安全な経路で渡します。
3. 必要に応じて役割変更または無効化を行います。

## 部署と従業員台帳

1. 「従業員」から「部署を管理」を開き、部署コードと部署名を登録します。
2. 従業員を追加し、社員番号、氏名、雇用区分、入社日、所属部署を入力します。
3. 従業員詳細でログイン利用者を紐付けます。紐付け後、本人が勤務実績とプロフィールを利用できます。

## 勤務ルール

1. 「勤怠」から「勤務ルール」を開きます。
2. 名称、適用開始日、所定開始・終了時刻、休憩時間、1日の所定労働時間を入力します。
3. 組織共通ルール、または特定従業員のルールとして保存します。

## 承認経路と承認担当者

1. 「利用者管理」で対象利用者の役割を「承認担当者」にします。承認担当者は従業員本人向け機能も引き続き利用できます。
2. 「承認経路」で部署、申請種別、担当者、適用開始・終了日、任意の対応期限日数を入力します。
3. 同じ部署・申請種別・期間の担当が重複しないことを確認して保存します。
4. 経路未設定の申請は管理者共通の未割当として「承認受信箱」に表示されます。まず既存申請を確認し、部署ごとに段階的に有効化してください。

経路は提出時に固定されます。提出後の異動や設定変更で既存ケースは暗黙に移動しません。

## 不在時の承認引継ぎ

1. 「承認引継ぎ」で元担当者、代理担当者、部署・申請種別、開始・終了日時、具体的な理由を入力します。
2. 既存の審査待ち件数をプレビューし、同時に移すケースだけを選択します。
3. 期間中の新規申請は代理担当へ届き、元担当者の記録も保持されます。
4. 終了後に代理担当へ残ったケースは自動で戻らないため、「承認受信箱」の「要再割当」を確認します。

承認担当者自身は別利用者へ再委任できません。所有者または労務管理者が設定します。

## 管理者による代理申請

「申請と審査」→「代理申請」で、対象従業員、休暇・勤怠修正・残業／休日出勤の内容、申請理由、具体的な代理作成理由を入力します。本人としてログインし直さず、実際の作成者を記録します。締め済み月、残高不足、重複、時刻矛盾などは本人申請と同じ条件で拒否されます。対象本人と代理作成者は同じ申請を審査できません。

完了後は[打刻・勤務実績・プロフィール](employee-attendance.md)で従業員の日常操作を確認してください。

勤務ルールの後に[勤務カレンダーの設定](work-calendar.md)と[休暇種別・付与・残高管理](leave-management.md)を進めます。

## 画面の目的

管理者が、従業員が日々の打刻と申請を始められる状態まで組織設定を整えます。

## 入力項目

部署、従業員番号、氏名、所属、入社日、勤務ルール名、所定時刻、休憩分数、適用開始日を入力します。画面内の必須・任意、単位、例、反映範囲を確認してください。

## 完了条件

従業員と利用者が紐付き、組織既定の勤務ルール、勤務カレンダー、休暇、残業申請設定が有効になれば初期設定は完了です。ホームの初期設定進捗でも確認できます。

## 次の操作

[打刻・勤務実績・プロフィール](employee-attendance.md)で従業員の初回操作を確認します。

## トラブル対処

登録できない項目がある場合は入力欄の説明とエラー要約を確認します。権限、重複、紐付けで解消しない場合は[トラブル対処](troubleshooting.md)を参照してください。

## 現行版の制限

時間単位休暇、自動法令判定、多段承認、条件分岐する承認経路には対応していません。通知はアプリ内だけです。集計と申請承認は法令や就業規則への適合を判定するものではありません。
