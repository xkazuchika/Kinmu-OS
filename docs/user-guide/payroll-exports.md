# 給与連携CSVの設定・検査・出力

対象バージョン: 0.6.0

## 給与連携でできること

所有者と労務管理者は、締め済み勤怠から従業員一人につき一行のCSVを生成できます。文字コード、改行、ファイル名、列順、参照項目、固定値、空欄、変換、必須、数式注入対策をプロファイルとして管理します。

出力は締めリビジョン、公開プロファイル版、外部従業員コードの版を固定したrunとして保存されます。保存済みrunは、同じ条件から再生成したSHA-256が一致した場合だけ再ダウンロードできます。

月次締めの考え方は[月次勤怠の締め・再開](monthly-closing.md)、操作履歴は[レポート・CSV・監査ログ](reports-and-audit.md)も参照してください。

## 初回設定

1. 「給与連携」の「プロファイル」を開きます。
2. migrationで作られた「汎用給与連携」のドラフトを開きます。
3. 利用先の仕様書に合わせて文字コード、改行、ファイル名と列を編集します。
4. 「ドラフトを保存・検査」で設定エラーがないことを確認します。
5. 公開確認で列数と文字コードを再確認し、不変の公開版を作成します。
6. 「従業員コード」で給与ソフト側の外部従業員コードを設定します。

ファイル名には `{targetMonth}` が必要です。`{revision}` と `{profileName}` も使用できます。任意式、列間参照、スクリプト、利用者が入力したコードの実行はできません。

## プロファイルと版管理

公開版は過去runを再現するため変更も削除もされません。設定を変える場合は公開版から新しいドラフトを作り、保存・検査後に次の版として公開します。

利用先が複数ある場合はプロファイルを複製し、目的が分かる名前を付けます。アーカイブは未使用ドラフトを通常一覧から外す操作で、公開版と過去runは保持します。

設定JSONの移出には列設定だけが含まれます。組織、個人、外部従業員コード、出力runは含みません。取込時は全設定を検査し、新しい未公開ドラフトとして保存します。

## 外部従業員コード

外部従業員コードはプロファイルごとに設定します。画面から一名ずつ保存するか、UTF-8 BOMのCSVテンプレートを取得して全行検査後に一括反映します。

CSVに未知の従業員番号、空値、重複、長すぎる値、別の従業員が使用中のコードがある場合は一件も反映しません。検査後に誰かがコードを変更した場合も競合として停止するため、CSVを再検査します。

コード値は出力に必要な個人情報です。通常ログと監査一覧には値そのものを表示せず、設定・変更・解除・一括反映の事実と件数だけを記録します。

## 全件検査とCSV生成

1. 対象月と公開プロファイル版を選びます。
2. 「全件検査を実行」で締め対象者全員を検査します。
3. 外部コード、必須値、型、長さ、CP932、数式注入のエラーと警告を解消します。
4. 変換前後プレビューで、行数、列順、時間変換、固定値を確認します。
5. 生成確認で対象月、締めリビジョン、プロファイル版、行・列数、文字コード、丸め、警告を確認します。
6. CSVを生成し、利用先で件数と時間合計を照合します。

検査後に月次再開、プロファイル公開、外部コード変更が行われた場合、生成は競合として停止します。表示中の検査結果を信頼せず、もう一度全件検査してください。

## トラブル対処

- CP932で表現できない: 氏名や部署名などの該当文字を利用先と確認し、UTF-8 BOMへ変更するか、台帳側の正式表記を見直します。文字を黙って置換して出力することはありません。
- 必須値が空: 問題に表示された従業員と列を確認し、従業員台帳、締め内容、外部コード、または必須設定を修正します。
- コードが重複する: 一つのプロファイル内で外部コードが一意になるよう修正し、CSV取込は全行を再検査します。
- 数式注入候補がある: `=`, `+`, `-`, `@` などで始まる文字列です。値を見直すか、利用先が許容する場合だけ警告付きのアポストロフィ付加を設定します。
- 競合になった: 月次締め、公開版、外部コードのいずれかが変わっています。ページを再読み込みして全件検査からやり直します。
- 旧リビジョンと表示される: 月次再開・再締めにより新しい締め版が作られています。旧runは証跡として保持し、現在版から新しいrunを生成します。
- SHA-256が一致しない: ファイルは返されません。アプリとDBの組合せ、generator version、復元状態を確認し、監査ログを保全して調査します。

## 再開・再締め後の差し替え

締め後の勤怠を修正する場合は、利用先へ差し替え理由を説明できるよう月次再開の理由を具体的に記録します。修正と審査を終えて再締めし、「給与連携」で新しいリビジョンを全件検査して生成します。

旧runを削除したり上書きしたりせず、新旧のrun ID、締めリビジョン、SHA-256、利用先へ渡した日時を対応付けます。誤使用を避けるため、旧CSVを共有フォルダの通常取込場所へ残さないでください。

## バックアップ・復元と受渡し確認

更新前、月次締め前後、給与連携run生成後にPostgreSQLバックアップを取得します。復元時は空DBへ戻し、migration適用後にログイン、締めリビジョン、公開プロファイル版、コード対応、run一覧、再ダウンロードのSHA-256を確認します。

設定JSONだけでは外部コードとrunを復元できません。通常バックアップと併用してください。v0.6データを作成したDBへv0.5アプリを接続する運用は保証しません。戻す場合はv0.6更新前バックアップを別の空DBへ復元します。

CSVを利用先へ渡した後は、最低でも対象月、従業員件数、列数、実働・残業・休暇・欠勤の合計、文字化け、先頭ゼロ、負数、24時間を超える時間、丸めを確認します。

## 現行版の制限

給与・税・社会保険・割増賃金の計算、法令や就業規則への適合判定、振込、給与明細、給与ソフトとのAPI同期、任意式、ベンダー別プリセットには対応していません。生成CSVは給与計算結果ではなく、締め済み勤怠を利用先へ渡すための連携ファイルです。
