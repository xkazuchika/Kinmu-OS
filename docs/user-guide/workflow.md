# 業務の全体フロー

対象バージョン: 0.8.0

Kinmu-OSで初期設定から月次の出力まで進める順序です。申請は必要なときだけ行い、承認・差し戻しは申請がある場合に発生します。各操作の詳しい手順は、下のリンクから確認できます。

## 全体の流れ

```
初回: 組織・従業員・勤務設定
  ↓
日々: 打刻・勤務実績の確認
  ├→ 必要なときは申請 → 審査・結果確認
  ↓
月末後: 未完了・要対応を解消
  ↓
月次締め → 勤怠CSVの保管
              ↓
        必要なら給与連携CSV
```

差し戻された申請は修正して再申請するか、取り消します。審査待ちや未解決の勤務日が残っている月は締められません。

## 段階ごとの担当と手順

1. 初回設定（所有者・労務管理者）: [初期設定と従業員管理](admin-setup.md)で組織、利用者、部署、従業員と勤務ルールを準備します。[勤務カレンダー](work-calendar.md)、[休暇種別と残高](leave-management.md)、[残業申請ポリシー](overtime-management.md)を設定し、必要な部署・申請種別には承認経路を設定します。給与連携を利用する組織は、[給与プロファイルと外部従業員コード](payroll-exports.md)も準備します。
2. 日々の記録（従業員・承認担当者）: [出退勤と休憩を打刻](employee-attendance.md)し、勤務実績を確認します。必要に応じて[休暇](leave-requests.md)、[残業・休日出勤](overtime-requests.md)、[勤怠修正](attendance-corrections.md)を申請します。所有者・労務管理者は理由を記録して代理申請することもできます。
3. 審査と解消（割当先の承認担当者・所有者・労務管理者）: 申請は設定された担当者の「承認受信箱」に届きます。経路未設定は管理者共通の未割当です。内容を確認して承認・却下・差し戻しを行い、差し戻された人は「申請履歴」から修正・再申請または取消を行います。本人と代理作成者はその申請を自己審査できません。[通知と要対応一覧](notifications.md)で未退勤、未解決日、承認期限超過、再申請待ちを確認できます。
4. 月次締め（所有者・労務管理者）: 対象月が終了した後、[月次勤怠の締め・再開](monthly-closing.md)で未退勤、未解決日、審査待ち・差し戻し中の申請などの阻害件数を0にします。勤務実績と集計を確認して締め、[勤怠CSV](reports-and-audit.md)をリビジョンとともに保管します。
5. 外部への受渡し（所有者・労務管理者）: 給与連携を利用する場合だけ、締め済み月と公開済みプロファイルを[全件検査して給与連携CSVを生成](payroll-exports.md)します。利用先で件数と時間の合計を照合します。このCSVは給与計算結果ではありません。

締め後に修正が必要になった場合は、理由を記録して月を再開し、修正・審査後に再締めします。新しいリビジョンの勤怠CSVを保管し、給与連携CSVを利用していた場合は再検査・再生成して受渡し先へ差し替えを伝えます。詳しくは[月次勤怠の締め・再開](monthly-closing.md)と[給与連携CSVの設定・検査・出力](payroll-exports.md)を参照してください。

## 現行版の制限

時間単位休暇、自動法令判定、多段承認、給与・税・社会保険の計算には対応していません。申請の審査、勤怠の集計、CSV出力は法令や就業規則への適合を判定するものではありません。
