# Kinmu-OS v0.8.0 リリース候補レビュー

- 対象バージョン: 0.8.0
- 予定タグ: `v0.8.0`
- 変更: 承認経路、承認担当者、横断受信箱、差し戻し・不変改訂、引継ぎ・再割当、管理者代理申請、全申請通知、承認監査検索

## リリース判定条件

- v0.7相当データの加算マイグレーションと移行検査が成功する
- 3申請種別で提出、差し戻し、再申請、取消、承認、却下が原子的に動作する
- approverが現在割当だけを閲覧し、他ケースの存在・内容・件数を推測できない
- 対象本人と代理作成者の自己審査を拒否する
- 通知がケース版・操作・受信者単位で重複せず、再割当・役割変更後に再認可される
- pendingとreturnedが月次締めを阻害する
- 320 CSSピクセル以上で主要承認操作に横スクロールがない
- format、lint、typecheck、全テスト、本番build、依存関係・ライセンス・秘密情報検査、OpenSpec strict validationが成功する

## 更新と切り戻し

[v0.8更新ガイド](v0.8-upgrade.md)に従い、更新前バックアップ、移行件数照合、段階的な経路有効化、空DBへの復元切り戻しを実施します。v0.8データを持つDBへv0.7アプリを直接接続しません。

## 既知の制限

時間単位休暇、多段承認、金額・役職等による経路分岐、メール・外部チャット通知、自動法令判定、給与計算は対象外です。承認・集計は就業規則や法令への適合を保証しません。

### 検証中に修正した不具合

- `.test.tsx`がVitestの対象外だったため、TSXも収集するよう変更した。CIに専用DBでのChromium E2Eを追加した。
- バックアップ・復元がホスト側のDB既定値を参照していたため、DBコンテナの設定を使うよう変更した。作成開始時の権限、失敗時の一時ファイル削除、完成名の上書き拒否、復元の単一トランザクションも確認した。
- macOSのmktempで接尾辞付きテンプレートが一意名にならないケースを再現し、ランダム文字列を末尾に置く互換形式へ修正した。
- DBに接続できなくてもhealthが200だったため、期限付きDB問い合わせに変更した。
- v0.8の審査操作後に、申請とケースの記録時刻の1〜3ms差で次回更新が止まる不具合を再現した。審査詳細の移行時完全一致は業務操作前のversion 0に限定し、件数・状態・現在改訂・休暇予約の全件照合は維持した。過去データの書換えは行わない。

### 検証範囲の限界

GitHub上のCI実行は未確認で、追加した手順をローカルで実行した。Firefox／WebKit、外部TLSプロキシ、実業務データ、長期同時負荷、v0.7イメージへの実際の切り戻しは今回の対象外。約2GiBのDocker VMで複数の環境を同時稼働させた際にbuild workerがSIGKILLされ、更新スクリプトが停止した。旧アプリが維持されることを確認し、検証コンテナ数を減らして再実行した。ビルド中のメモリ余裕も導入環境ごとに確認する。
