# Spec Delta

## Purpose

従業員・承認担当者・管理者が日々の勤怠と申請の対応漏れを一か所で把握し、現在の権限と業務状態に応じた解消操作へ進めるようにする。通知の既読と実際の業務完了を区別し、月次締めまでの確認・催促の負担を減らす。

## ADDED Requirements

### Requirement: 現在状態からの要対応事項の判定

システムは、組織タイムゾーンの現在日時を基準に、締め済みでない期間について、過去日の未退勤、過去の所定勤務日の未解決状態、期限超過の審査待ち申請、差し戻し中の未再申請を要対応として判定しなければならない（MUST）。勤務予定・在籍履歴・休暇・欠勤の判定は既存の勤怠一覧と一致させなければならない（MUST）。未解決日は勤務カレンダーの有効期間以降を対象とし、未退勤はそれ以前も記録がある限り対象に含める。既定表示は過去の未締め期間を含む全対象とし、直近月だけに暗黙で制限してはならない（MUST）。

#### Scenario: 前日の退勤記録がない
- **WHEN** 組織の現地日付が変わり、過去日に未退勤の記録がある
- **THEN** 要対応一覧に対象者・勤務日・未退勤である理由を表示し、当日の勤務中の記録は含めない

#### Scenario: 勤務予定に実績がない
- **WHEN** 過去日の既存勤怠判定が未解決である
- **THEN** 未解決として表示し、休日、全日休暇、欠勤確定、カレンダー未有効の日を未解決として追加しない

#### Scenario: 承認期限と差し戻しを確認する
- **WHEN** 審査待ち申請の期限が現在時刻より前、または申請が差し戻し中である
- **THEN** 前者を承認期限超過、後者を再申請待ちとして表示し、期限未設定・期限と同時刻の審査待ちは期限超過に含めない

#### Scenario: 古い未締め月に問題が残る
- **WHEN** 前々月以前の未締め期間に対象事項が残っている
- **THEN** 既定一覧と総件数に含め、対象月で絞り込んで確認できる

### Requirement: 役割別の閲覧範囲と次の担当

システムは、従業員には本人分、承認担当者には本人分と現在割当中の期限超過申請、所有者・労務管理者には同一組織の全対象を表示しなければならない（MUST）。件数・絞り込み候補・対象リンクにも同じ認可を適用しなければならない（MUST）。各事項に次の担当と現在許可される操作を表示し、自己審査禁止、代理作成者の自己審査禁止、無効担当者・終了済み引継ぎの再割当要否を既存承認規則と一致させなければならない（MUST）。

#### Scenario: 他者の条件を指定する
- **WHEN** 従業員が他者のIDや他組織の条件を指定して一覧・件数・対象を取得する
- **THEN** 許可外の内容と存在を返さず、不正な条件を拒否する

#### Scenario: 担当が再割当される
- **WHEN** 期限超過申請が別の担当者へ再割当された後に旧担当者が再取得する
- **THEN** 旧担当者の担当分一覧と件数から外れ、現在の担当者の範囲に反映される

#### Scenario: 審査を実行できない担当が設定されている
- **WHEN** 担当者が無効、引継ぎ終了、または自己審査になる期限超過申請がある
- **THEN** 管理者には審査を促す代わりに再割当・別の管理者への依頼など実行可能な対処を表示する

#### Scenario: 管理者が従業員の不備を見る
- **WHEN** 本人の修正が必要な勤怠や差し戻し申請を管理者が確認する
- **THEN** 対象本人と次の担当を区別し、本人・代理作成者・管理者の既存権限に応じた確認先を示す

### Requirement: 解消に追随する一覧と往復導線

システムは要対応一覧とホーム要約を同じ判定から生成し、取得時点の種類別・全体件数を示さなければならない（MUST）。対象操作後に戻った際は再取得し、解消済み事項を除外しなければならない（MUST）。一覧は月・種別・権限のある対象者と部署で絞り込み、50件単位の安定したページング、理由・次の担当・対象日・操作を提供しなければならない（MUST）。対応先には対象月・勤務日・申請を引き継ぎ、安全な戻り先で条件を復元しなければならない（MUST）。

#### Scenario: 退勤漏れを修正して戻る
- **WHEN** 勤怠修正が承認され未退勤が解消した後、元の条件の一覧へ戻る
- **THEN** 当該事項が一覧・ホーム件数から外れ、残る事項を最新状態で確認できる

#### Scenario: 差し戻し後に再申請する
- **WHEN** 差し戻し申請を再申請または取消しして戻る
- **THEN** 再申請待ちの事項は消え、再申請の場合は通常の審査待ちになったことを申請詳細で確認できる

#### Scenario: 既読にしただけの不備が残る
- **WHEN** 未退勤の通知を既読にしたが業務状態は変わっていない
- **THEN** 要対応一覧には未退勤が残る

#### Scenario: 不備を直す申請が審査待ちである
- **WHEN** 勤怠の不備に関連する修正・休暇申請が審査待ちである
- **THEN** 元の不備は承認・反映まで残し、関連申請と審査待ちであることを示して重複申請を促さない

#### Scenario: 狭い画面や取得失敗を扱う
- **WHEN** 幅320 CSSピクセルで一覧を開く、または取得に失敗する
- **THEN** 正常時は横スクロールなしで主要項目と操作に到達でき、失敗時は要対応0件と表示せず再試行を案内する

#### Scenario: 対象期間が締められる
- **WHEN** 要対応表示後に対象期間が締め済みとなり再取得する
- **THEN** 対象を要対応から外し、古いリンクから編集制限を迂回できない
