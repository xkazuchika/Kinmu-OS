# Spec Delta

## ADDED Requirements

### Requirement: 閲覧に依存しない定期リマインダー運用

本番Compose構成は、マイグレーション成功後に定期リマインダーを起動し、利用者のログインやページ閲覧がなくても実行しなければならない（MUST）。定期処理の正常・異常・最終成功時刻を導入者が確認でき、DB障害時に成功を偽装せず、復旧後に重複なく再実行できなければならない（MUST）。停止方法、手動の一回実行、開発環境での起動、更新・復元後の確認を文書化しなければならない（MUST）。

#### Scenario: 誰もログインしない朝になる
- **WHEN** 本番構成が正常稼働し、未解消事項がある組織で現地9時を迎える
- **THEN** ログイン要求なしに定期判定が走り、対象利用者のアプリ内通知が生成される

#### Scenario: DB障害から復旧する
- **WHEN** 定期処理中にDBが停止し、その後復旧する
- **THEN** 失敗と最終成功を区別して確認でき、処理は復旧後に再試行し、成功済み通知を複製しない

#### Scenario: 新しい版へ更新する
- **WHEN** 文書化された更新処理を実行する
- **THEN** 新版のappとworkerをビルドし、移行成功後だけ両方を更新する。ビルドまたは移行に失敗した場合は旧appを維持し、workerの停止・再開結果を明示する

#### Scenario: バックアップを復元する
- **WHEN** 空DBにバックアップを復元して対応版を起動する
- **THEN** 通知履歴と日次重複防止情報を復元し、業務データを変更せずに当日分のリマインダーを再実行できる
