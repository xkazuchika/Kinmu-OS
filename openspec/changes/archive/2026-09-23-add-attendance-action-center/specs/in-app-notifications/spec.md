# Spec Delta

## ADDED Requirements

### Requirement: 日次の要対応リマインダー

システムは、組織の現地時刻9時以降に未解消の要対応事項がある有効な利用者へ、1利用者・1組織・現地日付につき最大1件のアプリ内ダイジェストを作成しなければならない（MUST）。正常稼働中は15分以内の間隔で対象判定を行い、当日9時以降に新たに対象となった未通知の利用者も検査しなければならない（MUST）。差し戻しは即時イベント通知との重複催促を避け、差し戻された現地日付の翌日以降に日次対象とし、一覧には当日から表示する。未退勤・未解決は過去日、承認期限超過は現在状態を対象としなければならない（MUST）。

通知対象は本人の勤怠・差し戻し、現在の審査担当者の期限超過、管理者の組織内未解消事項とし、兼務時も1件へまとめなければならない（MUST）。未割当・要再割当は管理者へ案内し、対象0件または無効な利用者には作成してはならない（MUST）。

#### Scenario: 翌朝に未退勤が残る
- **WHEN** 現地9時以降の判定で本人の過去日の未退勤がある
- **THEN** 本人と管理者のそれぞれに、その日の要対応ダイジェストを最大1件作成する

#### Scenario: 同じ日に何度も判定する
- **WHEN** 再試行、workerの並行実行、再起動、タイムゾーンの夏時間重複で同じ通知日を再処理する
- **THEN** 同じ受信者・組織・現地日付の通知は増えず、既読状態を戻さない

#### Scenario: 差し戻された当日である
- **WHEN** 当日差し戻された申請だけがある
- **THEN** 即時の差し戻し通知と要対応一覧は利用できるが、日次催促は翌日以降まで作成しない

#### Scenario: 停止後に再開する
- **WHEN** workerが複数日停止した後、現地9時以降に再開する
- **THEN** 現在の未解消事項について当日分だけを作成し、停止中の日数分をまとめて作成しない

#### Scenario: 解消した次の日になる
- **WHEN** 前日に存在した事項が解消され、他に日次通知対象がない
- **THEN** 新しいリマインダーは作成しない

### Requirement: リマインダーの安全な内容と遷移

リマインダーは対象の氏名、申請理由、代理理由、詳細件数を固定の本文として保存せず、要対応確認を促す最小限の文言と通知日を表示しなければならない（MUST）。開く際は現在の認証・組織・役割で要対応一覧を再取得し、権限喪失後の対象情報を露出してはならない（MUST）。通知の既読と業務解消は独立して扱わなければならない（MUST）。

#### Scenario: 通知後に全件解消する
- **WHEN** 受信者が全件解消後に過去のリマインダーを開く
- **THEN** 通知を既読にして現在の要対応一覧へ移動し、対象がないことを表示する

#### Scenario: 受信者の役割が変わる
- **WHEN** 管理者から従業員へ変更された利用者が過去のリマインダーを読む
- **THEN** 本文から他者情報を読み取れず、遷移先には本人の現在許可された事項だけを表示する
