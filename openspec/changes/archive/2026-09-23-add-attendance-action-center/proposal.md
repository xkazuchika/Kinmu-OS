# Proposal

## Why

未退勤・未解決日の件数、承認期限、差し戻しは既存画面で確認できるが、本人や管理者が画面を巡回して対応漏れを探す必要がある。要対応事項と解消導線を一か所へ集め、日次のアプリ内通知によって月次締め前の確認・催促の負担を減らす。

## What Changes

- 役割別の「要対応」一覧とホームの要約を追加する。過去日の未退勤、未解決の勤務日、期限超過の承認待ち、差し戻し後の未再申請を対象とする。
- 対象者、対象日、理由、次の担当、次の操作を表示し、既存の勤怠修正・休暇申請・欠勤確定・審査・再申請へ業務文脈を保持して移動する。
- 一覧は現在の勤怠・申請状態から判定し、解消後の再取得で対象を外す。既読操作を業務完了として扱わない。
- 組織の現地時刻9時以降、未解消事項がある有効な利用者へ1日1回のアプリ内ダイジェストを作る。重複実行・再起動でも二重作成せず、過去の通知日は遡って配信しない。
- ログインや画面閲覧に依存しないリマインダーworkerをComposeへ追加し、更新・復元・障害確認の手順とテストを整える。
- 今回は外部送信、手動一括催促、有休自動付与、法令判定、締め日変更を含めない。

## Capabilities

### New Capabilities

- `attendance-action-center`: 要対応事項の判定、役割別一覧、ホーム要約、最新状態に基づく解消と対応導線。

### Modified Capabilities

- `in-app-notifications`: 未解消事項の定期ダイジェスト、日次重複防止、権限と解消状態を再検査する通知導線を追加する。
- `self-hosted-operations`: 定期workerの起動・監視・更新・復元と失敗時の再実行要件を追加する。

## Impact

- 既存の `attendance-operations.ts`、`approval-cases.ts`、`approval-review.ts` の判定・権限と整合する共通読取サービス、要対応API・画面、ホーム・ナビゲーションを追加する。
- `notifications.ts`、DB通知種別と加算マイグレーション、通知画面・対象導線へ拡張を加える。業務データの締め状態や審査結果は変更しない。
- Dockerfile、Compose、`scripts/update.sh`、package scripts、利用ガイドと運用資料を更新する。外部サービスや新しいメッセージ基盤への依存は追加しない。
- 単体・DB統合・移行・並行実行・100名性能・ブラウザ・Compose運用テストを追加する。
